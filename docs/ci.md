# CI and release workflows

All four workflows were written and linted with actionlint 1.7.12 (no findings), and the shell step of `release.yml` that collects outputs was run locally with fake build files.
**None of them has run on GitHub yet.** Action versions are pinned by commit SHA (tag in the trailing comment). Re-check them when updating.

| workflow | trigger | what it does |
|---|---|---|
| `ci.yml` | every push and PR | `scripts`: runs the script unit tests, restores the verified-bundle cache, fetches + verifies the pinned native tool releases (yt-dlp, cpython, ffmpeg) for all ABIs with the real script (while `native/bundle.lock.json` is UNPINNED it first pins the newest release of each tool, verified), uploads `BUILD_INFO.native.json`. `android`: if `gradlew` exists, fetches the bundle, then `assembleDebug testDebugUnitTest lintDebug`, uploads APK and reports; if not, it prints a notice that Android steps were SKIPPED (not passed). |
| `native-health.yml` | Mondays 03:17 UTC + manual | `fetch_native_bundle.py check` (pinned URLs reachable, pinned size), a cache-free full download + verification, and `update_native_bundle.py discover` (information only). Never changes the manifest. Log uploaded. |
| `poc.yml` | manual + pushes that touch app/native/scripts/gradle | The Phase 1 proof of concept. Matrix x86_64 and x86 on API 24 and 34: fetches only that ABI, builds the debug and androidTest APKs first, then starts an emulator and runs `scripts/run_instrumented_tests.sh`, which waits until adb reports the one emulator as `device` and booted, checks its API level (>= minSdk 24 and equal to the matrix API) and ABI list (must contain the packaged ABI), and only then runs `connectedDebugAndroidTest -PnativeAbis=<abi>` (all modules; on failure it uploads `build/ci/device-diagnostics.txt`) (13 instrumented tests executing the real CPython, yt-dlp and FFmpeg). `scripts/summarize_junit.py` writes the PASS/FAIL list to the job summary and FAILS when zero tests ran or any failed/was skipped. It never edits the manifest. ARM ABIs cannot be tested on hosted runners. |
| `release.yml` | push of a tag `v*`, or manual with a version | For each ABI (arm64-v8a, armeabi-v7a, x86, x86_64; owner decision) builds one debug APK and one release APK containing only that ABI's native runtime, names them `viddown-<version>-<debug|release>-<abi>[-UNSIGNED].apk`, writes `SHA256SUMS.txt`, `BUILD_INFO.app.json`, the native provenance and `RELEASE_NOTES.md` (generated by `scripts/release_notes.py`; it labels every ABI without a PASS runtime check as NOT VERIFIED), then creates a **draft pre-release** with `gh release create`. A person must press Publish. Ordinary commits never trigger it. Fails with a clear error if `gradlew` does not exist. No AAB: it would ship every ABI's runtime to every device. |

Permissions are `contents: read` everywhere except the final `draft-release` job (`contents: write`).

## Contract the Gradle project (Phase 2) must satisfy

1. `gradlew` is committed; Java 17 builds it; module `:app` exists with tasks `assembleDebug`, `assembleRelease`, `bundleRelease`.
2. `-PnativeDir=build/native`: where the fetched, verified bundle lives (`build/native/<abi>/jniLibs`, `build/native/<abi>/assets`).
3. `-PnativeAbis=<comma list>`: ABIs whose native runtime is packaged. `ci.yml` debug builds pass the output of `scripts/verified_abis.py` (only PASS ABIs); `release.yml` builds each of the four ABIs separately by owner decision and labels the unverified ones; the PoC workflow passes the ABI under test. `app/build.gradle.kts` implements this (abiFilters + jniLibs/assets from `-PnativeDir`) and prints a NOTE when an ABI without PASS is packaged. With an empty list the APK is built without the yt-dlp runtime and the yt-dlp engine must report "Not available in this build".
4. Signing is read from environment variables set by the workflow only when all four secrets exist: `VIDDOWN_KEYSTORE_PATH`, `VIDDOWN_KEYSTORE_PASSWORD`, `VIDDOWN_KEY_ALIAS`, `VIDDOWN_KEY_PASSWORD`. When they are absent the release build must still succeed and produce an unsigned APK.
5. Repository secrets to create (Settings > Secrets and variables > Actions): `ANDROID_KEYSTORE_BASE64` (base64 of the .jks), `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD`. Never commit a keystore (`.gitignore` blocks `*.jks`/`*.keystore`).
6. Test results and lint reports are uploaded from `**/build/reports/**` and `**/build/test-results/**`.

## Later
* NewPipe engine: no workflow checks out submodules any more. Every Gradle workflow runs `python3 scripts/fetch_newpipe.py ensure` (after setup-python and setup-java), which clones the LATEST stable NewPipeExtractor release and the nanojson commit it names into `third_party/` (git-ignored); `settings.gradle.kts` runs the same script again, so a plain `./gradlew` works too. JDK 11, 21 and 17 are installed (17 last, so it runs Gradle) and `~/.gradle/gradle.properties` gets `org.gradle.java.installations.fromEnv=JAVA_HOME_11_X64,JAVA_HOME_17_X64,JAVA_HOME_21_X64` so whichever toolchain the fetched extractor asks for is found (17 for v0.27.x). The release workflow stores the exact version in `BUILD_INFO.newpipe.json`. To build an older release set `NEWPIPE_REF=v0.26.5` (repository variable or env).
